# Native adapter reliability evidence

The scoped review covers `AudioIngress`, `NativeAudioCapture`, `SourcePipeline`, `NativeScreenCapture` and `ModelInstaller`. This is separate from live microphone/system capture and model accuracy benchmarks.

The review repaired three concrete timing/data-loss defects: the first overflow permanently disabled subsequent device/timestamp-gap checks; overflow intervals were guessed from the next retained frame rather than capture timestamps; and a 15-second STT window boundary could discard the tail of a 20 ms chunk when the boundary fell inside a native frame. Overflow records now preserve a coalesced source-time envelope and the actual summed dropped-sample duration. Callback contention uses a bounded atomic envelope with a single producer and consumer; the callback never waits for the consumer. The worker now splits at the exact window boundary and continues with the retained tail. Tests exercise 1024-sample native blocks crossing the 240,000-sample window boundary and concurrent callback/consumer sample conservation.

Ingress retains at most two seconds and 256 frames per source. A worker can additionally own a drained batch of at most two seconds plus one 15-second analysis window. These are distinct finite allocations; `retainedBatchSeconds` exposes the worker-owned backlog and `queuedSeconds` reads current ingress state even during inference. `windowProcessingDelay` remains window-end-to-hypothesis delay, not token-aligned speech latency. `realTimeFactor` divides accumulated inference time by unique audio admitted to analysis windows; benchmark token/word timing and whole-session throughput remain separate evidence.

Microphone buffers use the documented `AVCaptureSession.synchronizationClock`, convert to the Core Media host clock, then map to `ProcessInfo.systemUptime`, matching the session origin. The system-audio adapter maps host timestamps into the same uptime domain. The microphone adapter now observes runtime error, interruption, unexpected stop, device disconnection, synchronization-clock replacement and changes to the system default input. A default-route change prompts the user to resume the source against the new default; it does not silently switch an active conversation's input. Shutdown invalidates callbacks, detaches native outputs/observers and drains the serial callback queue. A newer start invalidates an earlier suspended start.

The installed Apple SDK headers were checked on 2026-09-07: `AVCaptureSession.h` documents the synchronization clock and native notifications; `AVCaptureAudioDataOutput.h` describes callback efficiency and device-native formats; `SCStream.h` documents point/pixel scale and source rectangles. Source PCM is copied while the callback retains the native block; no borrowed PCM pointer crosses isolation. Unsupported unsigned/unpacked layouts are rejected. The native converter remains source-owned and resets across rate discontinuities.

Screenshot preparation now uses the selected filter's actual point/pixel scale rather than assuming every monitor is 2×. The 2048-pixel long-edge and 4 MiB PNG limits remain enforced. Consent/selection are checked around asynchronous source discovery and native acquisition and again before publication. Only the latest matching image ID, current selection epoch and an age between zero and 30 seconds pass freshness validation. One-shot `SCScreenshotManager` provides no explicit per-request cancellation handle in the macOS 15 API used here: task cancellation/consent revocation fences and discards late image completion. The caller owns and awaits the capture task; this is not a claim that an already-issued OS screenshot operation is instantly aborted.

The model installer validates the pinned HTTPS repository/revision/path and bounds individual sizes before summation. File verification uses a non-following file descriptor, checks regular-file type and exact byte count, rejects symlink ancestors, and hashes in bounded 256 KiB chunks with forwarded cancellation. Public Hugging Face redirects may reach HTTPS object storage; transport downgrades are rejected. A native advisory file lock protects actual installation transactions and allows a subsequent process to remove UUID-named orphan staging directories safely.

A complete verified directory is published using macOS `renameatx_np` with `RENAME_SWAP` for repair or `RENAME_EXCL` for an initial install. The pinned directory is the actual runtime lookup, so the previous unused `active-model` pointer no longer adds a second failure-prone publication step. Publication failure preserves the old directory; cleanup failure after a successful swap is logged as cleanup failure, not reported as a failed installation. The small lock file remains as coordination metadata when model bytes are removed. The macOS SDK `sys/stdio.h` declares atomic rename flags available since macOS 10.12.

Tests use actual temporary directories, files, SHA-256 verification, native rename/swap and file locking. The publication failure fixture removes directory write permission after staging: the real rename fails, the old model survives, permissions are restored and the next installation recovers the orphan stage. Only network fetch and free-capacity readings have injected test inputs; Release constructs the native URLSession download path and real volume-capacity check.

## Executed checks

```sh
  --filter 'AudioAdapterTests|NativePCMTests|SourcePipelineTests|ModelInstallerTests|VisualCaptureTests'
```

The run at 04:56:52 on 2026-09-07 passed **24 tests, zero failures, 1.132 s**. Coverage includes native PCM ownership, sequential resampling/rate changes, bounded queue loss conservation, later device gaps after overflow, exact window-edge continuity, actual model install/repair/permission failure/cancellation/lock/corruption/symlink/low-space paths, and screenshot cancellation/consent/selection/freshness/mixed-scale geometry.

Real microphone start after the synchronization-clock change, simultaneous real system capture, Bluetooth/disconnection hardware changes, mixed-scale/rotated monitor captures and actual screenshot crop contents require their own macOS app-bundle smoke checks. Pure geometry and scripted acquisition tests do not establish that platform coverage. An ad-hoc rebuild can require Screen & System Audio Recording permission to be granted again.
